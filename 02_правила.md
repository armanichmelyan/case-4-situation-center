## 2\. Формула severity (заполни)

deviation\_pct = (value - norm\_max) / norm\_max × 100 # при превышении
или (norm\_min - value) / norm\_min × 100 # при недоборе

Если 0 < deviation\_pct ≤ 5: severity = WARNING
Если 5 < deviation\_pct ≤ 10: severity = WARNING
Если deviation\_pct > 10: severity = CRITICAL
Если value = "" или нет данных: severity = STALE
Если norm\_min ≤ value ≤ norm\_max: severity = NORMAL

**Обоснование порогов:** 
Пороги заданы условиями кейса. При отклонении больше 0% и до 10% включительно устанавливается WARNING, при отклонении более 10% — CRITICAL с эскалацией руководителю. Порог 5% не влияет на результат: оба диапазона относятся к WARNING. Если данные отсутствуют, устанавливается STALE, поскольку без показаний нельзя определить, находится ли значение в норме. Если значение находится в пределах нормы, устанавливается NORMAL.

## 3\. Жизненный цикл инцидента

### Допустимые переходы (заполни)

|Из|В|Кто может|Условие|
|-|-|-|-|
|NEW|ASSIGNED|диспетчер или руководитель|назначен ответственный инженер|
|ASSIGNED|IN\_PROGRESS|инженер|ответственный инженер приступил к работе|
|IN\_PROGRESS|CLOSED|руководитель|работы по устранению проблемы завершены|
|ASSIGNED|CLOSED|руководитель|подтвержден ложный вызов, указано resolution_reason=NO_ACTION|

### Запрещённые переходы (заполни)

|Из|В|Почему запрещено|
|-|-|-|
|NEW|CLOSED|инцидент должен быть назначен и отработан|
|CLOSED|любой другой статус|закрытый инцидент нельзя переоткрывать; при необходимости создается новый|
|ASSIGNED|CLOSED|запрещено без resolution_reason=NO_ACTION: закрытие из ASSIGNED допускается только для ложного вызова|
|NEW|IN_PROGRESS|до начала работы должен быть назначен ответственный|
|ASSIGNED|NEW|возврат в NEW не предусмотрен жизненным циклом|
|IN_PROGRESS|NEW|возврат в NEW не предусмотрен жизненным циклом|
|IN_PROGRESS|ASSIGNED|возврат в ASSIGNED не предусмотрен жизненным циклом|

**Подсказки:**

* NEW → CLOSED напрямую нельзя: инцидент должен быть назначен и отработан.
* CLOSED → любой: переоткрывать нельзя, создаётся новый инцидент.
* ASSIGNED → CLOSED без IN\_PROGRESS: можно только с `resolution\\\_reason=NO\\\_ACTION` (ложный вызов).

## 6\. Дедупликация (заполни)

**Правило:** если в течение 5 минут пришло 2 события с одинаковыми
`location + indicator` — считать одно.

Как реализовать:
if (location, indicator) in seen and (now - seen\[(location, indicator)]) < 5 min:
→ игнорировать (DUPLICATE)
else:
→ обработать, обновить seen\[(location, indicator)] = now



**Порядок обработки в прототипе (уточнение команды):** приведенное выше «игнорировать» означает не создавать второй алерт, а не отбрасывать новое показание целиком. Сначала показание учитывается для серии CRITICAL (A-3) и времени последнего полученного показания (A-4), затем применяется дедупликация алерта (A-5). Поэтому два CRITICAL за три минуты могут создать автоинцидент, но второй алерт не создается. При изменении уровня обновляется существующий алерт. Окно A-5 отсчитывается от создания предыдущего алерта; повтор не продлевает это окно. Повторная доставка внешнего пакета с тем же event_id не считается новым показанием и второй раз в серии не учитывается.

**Вопрос:** почему это важно? Ответ: дедупликация предотвращает создание повторных оповещений по одному участку и показателю в течение пяти минут; это снижает нагрузку на диспетчера и помогает ему не отвлекаться на повторные сообщения об одной проблеме.
